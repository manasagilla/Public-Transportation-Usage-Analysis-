# Project 17: Public Transportation Usage Analysis

A beginner-friendly, reproducible R project analyzing real New York City MTA
subway ridership and transfer counts. The scripts clean the source extract,
create summary tables and charts, run statistical analyses, and render a
self-updating HTML report.

## Project structure

```text
.
|-- data/
|   |-- raw/           # Public MTA data extract, retained unchanged
|   `-- processed/    # Cleaned analysis dataset
|-- outputs/
|   |-- plots/         # Eight EDA plots
|   `-- tables/        # Cleaning, descriptive, comparison, and model tables
|-- R/
|   |-- helpers.R
|   |-- 01_data_cleaning.R
|   |-- 02_eda_visualizations.R
|   `-- 03_statistical_analysis.R
|-- report.Rmd
|-- dashboard/
|   `-- app.R        # Interactive Shiny dashboard
|-- run_project.R
`-- report.html       # Generated by the runner
```

## Dataset and scope

The source is the official [MTA Subway Hourly Ridership: 2020-2024 dataset on
NYC Open Data](https://data.ny.gov/Transportation/MTA-Subway-Hourly-Ridership-2020-2024/wujg-7c2s).
Its [Socrata CSV API](https://data.ny.gov/resource/wujg-7c2s.csv) provides the
timestamp, station complex, borough, ridership, and transfers. The project
uses the 2024 calendar year and aggregates fare/payment-category records to
one passenger and transfer total per station-hour.

For a fast, repeatable beginner workflow, the selected sample follows ten
station complexes throughout 2024: the five busiest and five least busy
among station complexes with positive reported totals on January 2, 2024.
The exact IDs are recorded in `R/01_data_cleaning.R`. The report therefore
describes these ten stations only; it is not a network-wide ranking or a
representative statistical sample. The script downloads the actual source
extract automatically if the raw CSV is absent. It does not substitute
synthetic data.

## Requirements

- Windows with R 4.1 or newer installed.
- VS Code with the R extension is recommended.
- R packages: `tidyverse`, `ggplot2`, `lubridate`, `janitor`, `broom`,
  `knitr`, `rmarkdown`, and `shiny`. `scales` and other tidyverse packages
  are also used for charts and data reshaping.

Install the required packages once in the R console:

```r
install.packages(
  c("tidyverse", "ggplot2", "lubridate", "janitor", "broom", "knitr", "rmarkdown", "shiny"),
  repos = "https://cloud.r-project.org"
)
```

The scripts check for required packages and print an install command if one
is missing. R Markdown also needs a LaTeX-free HTML-capable `rmarkdown`
installation; no LaTeX setup is required.

## Run in VS Code on Windows

1. Open this project folder in VS Code.
2. Open **Terminal > New Terminal**. The terminal's current folder should be
   this project folder (the one containing `run_project.R`).
3. Run:

   ```powershell
   & "C:\Program Files\R\R-4.6.1\bin\Rscript.exe" "run_project.R"
   ```

   If R is installed in a different folder, replace the executable path with
   the path to your `Rscript.exe`. Alternatively, if `Rscript` is on your
   Windows PATH, use:

   ```powershell
   Rscript run_project.R
   ```

4. Wait for the download, analysis, and report rendering to finish. Open
   `report.html` in a browser.

## Launch the interactive dashboard

After installing the packages and running the project once, open a VS Code
terminal in the project folder and run:

```powershell
Rscript -e "shiny::runApp('dashboard', host='127.0.0.1', port=8765, launch.browser=TRUE)"
```

If `Rscript` is not on your PATH, run:

```powershell
& "C:\Program Files\R\R-4.6.1\bin\Rscript.exe" -e "shiny::runApp('dashboard', host='127.0.0.1', port=8765, launch.browser=TRUE)"
```

The dashboard includes five interactive charts; date, station, weekday/weekend,
and passenger/transfer filters; summary cards; a station-level summary table;
and a CSV download for the selected data. Select **Reset filters** to restore
the full 2024 view. Leave the terminal running while using the dashboard; press
Ctrl+C there to stop its local server.

Run individual scripts in order, from the project folder, if desired:

```powershell
Rscript "R/01_data_cleaning.R"
Rscript "R/02_eda_visualizations.R"
Rscript "R/03_statistical_analysis.R"
Rscript -e "source('R/helpers.R'); configure_pandoc(); rmarkdown::render('report.Rmd', output_file='report.html')"
```

All paths are project-relative. The cleaning script creates the folder
structure and fetches the public CSV to `data/raw/` if it is missing.
Subsequent scripts read the saved cleaned CSV, so rerunning the project does
not need to redownload the source unless that raw file is removed.

## Outputs

- `data/raw/mta_subway_ridership_2024_selected_stations.csv` — downloaded
  source records, including fare/payment categories.
- `data/processed/mta_subway_ridership_2024_clean.csv` — cleaned analysis data.
- `outputs/plots/01_...png` through `08_...png` — eight focused EDA charts:
  station demand, daily trend, hourly demand, weekday/hour heat map, and
  weekday/weekend box plot, monthly average, federal-holiday comparison, and
  station-faceted passenger/transfer relationship.
- `outputs/tables/` — cleaning log, station coverage, station/day/hour/month/
  holiday/season summaries, descriptive statistics, paired test, model
  results, and numeric regression assumption checks.
- `report.html` — complete report regenerated from source data and analysis.

## Cleaning and interpretation notes

Invalid timestamps, missing required fields, negative counts, records outside
2024, and duplicate station/fare-category/timestamp rows are excluded.
Fare-category rows are summed to station-hour counts. Counts are never
imputed. Extreme nonnegative passenger counts are flagged using a high-tail
IQR rule and retained because a large value may be a genuine peak. The source
does not report every possible station-hour. Missing hours are not filled with
zeros; the cleaning summary reports coverage by station. Weekday/weekend and
holiday summaries and the box plot use only station-days with all 24 hourly
records. Daily trend values are means over the hours actually reported.
The MTA timestamps have no UTC offset; the scripts retain the published
wall-clock hour instead of converting time zones.

Federal holiday dates are added as an analysis indicator because the dataset
does not supply a holiday field. The paired Wilcoxon test compares station
weekday and weekend means. The OLS regression uses log(1 + passengers), with
station, hour, and month terms. Numeric residual checks are saved as a table.
The data are observational and hourly counts
may be serially dependent; associations are not causal claims, and model
p-values should be interpreted cautiously.
